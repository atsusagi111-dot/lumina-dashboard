# /simplify — シンプル化（LUMINA 案件用）

`/code-review` の指摘を反映した後に実行する。対象は現在のタスクで変更したファイル。

## 大原則

**挙動は絶対に変えない。** リファクタ（整理）前後で以下が同じ結果になることを確認する。
- `pnpm type-check` / `pnpm lint` / `pnpm test` が通る（スクリプトが無いものは手動実行で代替）
- KPI の計算結果が `docs/sample-data.md` の正解値と一致したまま

## チェック項目

1. **重複の削除**：同じ処理が 3 箇所以上にあれば 1 つの関数にまとめる（2 箇所だけなら無理にまとめない）
2. **不要な抽象化の除去**：1 箇所でしか使わない汎用クラス・ラッパー・設定オブジェクトを、直接の処理に戻す
3. **関数分割**：1 つの関数が 40 行を超える、または「〜して、さらに〜する」と 2 つ以上の責務を持つなら分ける
4. **可読性**：分かりにくい変数名を意味のある名前にする / ネストが 3 段を超えるなら早期 return にする / マジックナンバーを定数にする
5. **コメント**：「何をしているか」ではなく「なぜそうしているか」だけ残す。初心者向けの補足コメントは残す
6. **Markdown の場合**：重複した説明の統合、見出し階層の整理、長すぎる段落の分割

## 出力形式

1. 変更前に「何をどう簡素化するか」を箇条書きで提示
2. 適用
3. 確認コマンドの結果（型・Lint・テスト）を報告
4. 「挙動は変わっていない」根拠を一言で示す
