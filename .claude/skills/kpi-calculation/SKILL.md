# KPI 集計 手順書

## 設計方針
- すべて `lib/kpi/` の **純粋関数**（入力 → 出力のみ。DB や API に触らない）で実装する。理由：テストしやすく、Excel の値と突き合わせやすい。
- 入力は `SalesRow[]`（列は README §6 の仕様と同じ）。
- 月キーは `YYYY-MM` 文字列で扱う。
- 端数の扱いは下の「端数と境界の扱い」を参照（唯一の正）。

## KPI の定義

| KPI | 定義 | 計算式 |
| --- | --- | --- |
| 売上 | 当月の `revenue` 合計 | `sum(revenue)` |
| 粗利 | 売上 − 原価 | `sum(revenue) - sum(cost)` |
| 粗利率 | 粗利 ÷ 売上 | `粗利 / 売上 × 100`（売上 0 なら `null`） |
| リピート率（月次） | 当月購入者のうち、**その月より前に購入履歴がある顧客** の割合 | `(当月購入者 ∩ 過去購入者) / 当月購入者 × 100` |
| リピート率（全期間） | 全顧客のうち、**2 ヶ月以上で購入した顧客** の割合 | `2 ヶ月以上購入した顧客数 / 総顧客数 × 100` |
| 前月比 | 当月と前月の差を前月に対する割合で示す | `(当月 - 前月) / 前月 × 100`（前月データ無しなら `null`） |
| カテゴリ別売上 | カテゴリごとの `revenue` 合計（降順） | `groupBy(category) → sum(revenue)` |
| SKU トップ 10 | SKU ごとの `revenue` 合計の上位 10 件（数量も併記） | `groupBy(sku) → sum(revenue), sum(quantity)` → 降順 → 10 件 |
| 在庫回転率 | Phase 2（在庫データが無いため MVP では算出しない） | — |

補足：
- `customer_id` が空の行はリピート率の計算から除外する（売上・粗利には含める）。
- 「当月購入者」は `customer_id` のユニーク数（同じ人が同月に 2 回買っても 1 人）。
- ダッシュボードの KPI カードには **月次リピート率** を表示し、全期間リピート率は補足として出す。

## 端数と境界の扱い（Task 4 で確定。実装は `lib/kpi/`）

1. **端数**：割合は小数第 1 位、金額は小数第 2 位（DB が `numeric(14,2)` のため）で四捨五入する。
   計算途中では丸めず、最後に 1 回だけ丸める（途中で丸めると誤差が積み重なる）。
2. **「前月」はカレンダー上の前月**。10 月のデータが無い場合、11 月を 9 月と比べず前月比を `null` にする。
3. **「計算できない」は `0` ではなく `null`**。売上 0 円のときの粗利率、購入者 0 人のときのリピート率など。
   画面では「—」と表示する。
4. **最初の月のリピート率は `0.0`**（`null` ではない）。過去の履歴が無いことは事実として確定しているため。
5. **カテゴリが空の行は「未分類」**にまとめる（売上からは落とさない）。
6. **SKU が空の行は SKU ランキングから除外**する（順位を付ける対象が無いため）。売上には含まれる。
7. **並び順は金額の降順、同額なら名前順**。実行するたびに順番が変わらないようにする。

## サンプルデータの正解値

正解値の表は **`docs/sample-data.md` が唯一の正**。ここには複製しない（2 箇所にあるとズレるため）。

## テスト（`tests/kpi/*.test.ts`、Vitest）
1. サンプル CSV は **取り込みと同じ検査**（`lib/sheets/validate-rows.ts`）を通してから使う。
   テスト専用の読み方をすると、本番では通らない形のデータで検証してしまうため
2. `docs/sample-data.md` の正解値と `toBe` / `toEqual` で **完全一致** させる（`toBeCloseTo` は使わない。丸め位置を仕様として固定するため）
3. 境界ケース：空配列 → 全 KPI が 0 or `null` / 1 ヶ月分だけ → 前月比 `null` / `customer_id` 空 → リピート率から除外
